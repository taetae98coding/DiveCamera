# 스펙 충돌 검증 가이드

## 목적

- 스펙 충돌 검증은 사용자 입력이 기존 스펙과 충돌하는지 확인하는 작업이다.
- 검증 결과는 별도 문서로 작성하지 않는다.
- 충돌이 없으면 다음 작업 단계로 진행한다.

## 검토 대상

- 사용자 입력에서 새 요구사항, 변경 요구사항, 전제 조건을 분리한다.
- 변경 범위와 직접 관련된 스펙 문서를 확인한다.
- 권한, 화면 전환, 플랫폼 정책처럼 여러 스펙이 공유하는 정책은 연관 스펙까지 함께 확인한다.
- 코드 상태는 현재 구현을 이해하기 위한 참고로만 사용하고, 충돌 여부는 사용자 입력과 스펙을 기준으로 판단한다.

## 충돌 기준

- 사용자 입력이 기존 스펙의 필수 동작과 동시에 만족될 수 없으면 충돌로 본다.
- 사용자 입력이 기존 플랫폼 정책이나 권한 정책을 바꾸면 충돌 또는 스펙 변경으로 본다.
- 사용자 입력의 용어가 기존 스펙의 용어와 다르게 쓰여 의미가 불명확하면 확인이 필요한 충돌로 본다.
- 사용자 입력이 구현 세부사항만 요구하고 도메인 동작이 불명확하면 필요한 도메인 기대 동작을 먼저 식별한다.

## 처리

- 명확한 신규 요구사항이면 관련 스펙을 먼저 갱신한 뒤 TC 문서, TC, 구현 순서로 진행한다.
- 사용자 입력의 전제가 사실과 다르거나 기존 스펙과 직접 충돌하면 진행하기 전에 사용자에게 확인한다.
- 장단점이 뚜렷한 선택이 필요하면 선택지와 영향을 짧게 설명하고 사용자에게 확인한다.
- 검증 과정에서 확인한 충돌 없음, 참고 문서 목록, 판단 근거를 스펙 문서에 남기지 않는다.
