# 카메라 미리보기 절전 (Camera Idle) — 스펙

> [요구사항](../requirement/camera-idle.md)과 [컨텍스트](../context/camera-idle.md)를 절충해 구현 가능한 동작을 확정한다. 코드 레벨 설명은 다루지 않는다.

## 상태 모델 (플랫폼 공통)

카메라 화면의 미리보기 영역은 두 상태를 가진다.

- **활성(Active)**: 미리보기가 켜져 카메라가 동작하며 화면에 실시간 영상이 보인다.
- **절전(Idle)**: 미리보기가 꺼져 카메라가 반납되고 화면은 검은 화면이다. (카메라 하드웨어 미동작 → 전력 절약)

## 동작 (플랫폼 공통)

- **진입**: 카메라 화면에 들어오면 **활성** 상태로 시작한다. (미리보기 자동 시작은 [카메라 미리보기 스펙](camera-preview.md))
- **자동 절전**: 활성 상태에서 **30초** 동안 사용자 입력이 없으면 **절전**으로 전환한다. 전환 시 미리보기를 화면에서 내려 카메라를 반납하고 검은 화면이 된다.
- **재개**: 절전 상태에서 재개 입력(아래)이 들어오면 다시 **활성**으로 전환해 미리보기를 켠다.
- **타이머 리셋**: 재개되거나 활성 상태에서 사용자 입력이 들어오면 30초 타이머를 다시 시작한다.

## 재개 입력 (플랫폼 공통)

- **화면 터치**: 검은 화면을 터치하면 재개한다. (양쪽 플랫폼 공통)
- 현재 단계에서는 **터치만** 재개 수단으로 둔다. 볼륨 키 등 다른 입력으로 깨우는 것은 범위 밖이다. (사유는 아래)

## 범위 밖 — 볼륨 키 재개

볼륨(업) 버튼으로 재개하는 동작은 현재 단계에서 **다루지 않는다.** 플랫폼 차이가 크기 때문이다(근거는 [컨텍스트 문서](../context/camera-idle.md) 참조): 볼륨 버튼은 Android 에서는 키 이벤트로 전달되지만 iOS 에서는 앱에 입력 이벤트로 전달되지 않아 공통 구현이 불가능하고, iOS 우회(`outputVolume` KVO)는 한계가 크다. 추후 다이브 하우징별 조작 방식을 다룰 때 재검토한다.
