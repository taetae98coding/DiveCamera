# 권한 요청 (Permission) — 스펙

> [요구사항](../requirement/permission.md)과 [컨텍스트](../context/permission.md)를 절충해 구현 가능한 동작을 확정한다. 코드 레벨 설명은 다루지 않는다.

## 화면 구성 (플랫폼 공통)

권한 요청 화면은 **권한 목록**과 **하단 고정 버튼 영역**으로 구성된다.

- **권한 목록**: 아직 허용되지 않은(미결정·거절) 권한 카드만 노출한다. 노출되는 카드는 모두 "미허용" 상태이므로 **상태 표시는 두지 않는다.** 각 카드는 다음을 표시한다.
  - 권한 이름
  - 용도 설명 (요구사항의 설명 문구)
  - "권한 요청" 동작
  - **허용이 완료된 카드는 목록에서 제거**된다. (모든 권한이 허용되면 목록은 비게 된다.)
- **하단 고정 버튼 영역** (항상 노출):
  - **카메라 실행 버튼**: 카메라 권한이 허용되어 있으면 활성화, 아니면 비활성화된다.
  - **앱 설정 이동 버튼**: 권한 목록 상태와 무관하게 항상 노출된다.

## 권한 상태 모델 (플랫폼 공통)

각 권한은 다음 상태 중 하나를 가진다.

- **미결정(notDetermined)**: 아직 요청한 적 없음 → 요청 시 시스템 다이얼로그 노출.
- **허용됨(granted)**.
- **거절됨(denied)**: 사용자가 거절. 재요청 시 시스템 다이얼로그가 다시 노출되지 않을 수 있음(영구 거절). 이 경우 설정에서만 되돌릴 수 있다.

## 카메라 실행 동작 (플랫폼 공통)

- **자동 실행**: 4개 권한이 모두 허용 상태가 되면 별도 조작 없이 카메라가 실행된다.
- **수동 실행**: 카메라 권한만 허용되어 있어도 카메라 실행 버튼으로 카메라를 실행할 수 있다.
- 즉, 실행 최소 조건은 "카메라 허용", 자동 실행 조건은 "4개 모두 허용"이다.

## 설정 이동 동작 (플랫폼 공통)

- 앱 설정 이동 버튼은 항상 하단에 노출된다. 특히 권한이 **거절됨(영구 거절 포함)** 상태여서 시스템 다이얼로그로 재요청이 불가능한 경우, 사용자는 이 버튼으로 앱 설정(권한 설정) 화면에서 직접 권한을 켤 수 있다.
- 사용자가 설정에서 권한을 변경하고 앱으로 돌아오면, 화면은 갱신된 권한 상태를 반영한다. (허용된 권한 카드는 목록에서 사라진다.)

## 플랫폼별 분기

플랫폼 차이로 공통 구현이 불가능한 항목만 아래에 정리한다. (근거는 [컨텍스트 문서](../context/permission.md) 참조)

### 사진 저장 권한

공통 구현이 불가능한 이유: Android 10+ 에서는 앱이 촬영한 사진/영상을 갤러리에 저장할 때 **요청할 런타임 권한 자체가 존재하지 않는다.** 반면 iOS 는 저장을 위해 사진 보관함 권한이 필요하다.

- **Android**
  - 사진 저장은 별도 권한 요청이 필요 없으므로, 사진 저장 카드는 **항상 "허용됨"** 으로 표시하고 요청 동작을 노출하지 않는다.
  - "4개 모두 허용" 자동 실행 판정에서 사진 저장은 **항상 충족된 것으로 간주**한다. (실질 판정 대상: 카메라·마이크·위치)
- **iOS**
  - 사진 저장은 사진 보관함의 **추가 전용(add-only)** 권한으로 요청한다. (기존 사진을 읽지 않으므로 read/write 권한은 요청하지 않는다.)
  - 자동 실행 판정에 사진 저장 권한도 포함된다.

### 위치 권한 다이얼로그

공통 구현이 불가능한 이유: Android 12+ 는 정확/대략 위치 선택 UI를 제공하고, iOS 는 사용 중 허용 모델을 사용한다.

- **Android**: 포그라운드 위치 권한을 요청한다. Android 12+ 에서는 정확/대략 선택 다이얼로그가 노출될 수 있으며, 둘 중 하나라도 허용되면 위치 권한은 "허용됨"으로 간주한다.
- **iOS**: "앱 사용 중 허용" 권한을 요청한다.

### 영구 거절 판정 및 설정 이동 노출

공통 구현이 불가능한 이유: 영구 거절로 전환되는 시점과 판정 방식이 플랫폼마다 다르다.

- **Android**: 사용자가 권한을 두 번 거절하면 시스템 다이얼로그가 더 이상 노출되지 않는다. 재요청 가능 여부 판정을 통해 설정 이동 노출 여부를 결정한다. 앱 설정 화면은 `Settings.ACTION_APPLICATION_DETAILS_SETTINGS` 로 연다.
- **iOS**: 한 번 거절(미결정이 아닌 상태)하면 재요청 시 시스템 다이얼로그가 노출되지 않는다. 거절 상태면 설정 이동을 노출한다. 앱 설정은 `UIApplication.openSettingsURLString` 로 연다.
