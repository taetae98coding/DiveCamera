# 화면 이동 (Navigation) — 스펙

> [요구사항](../requirement/navigation.md)과 [컨텍스트](../context/navigation.md)를 절충해 구현 가능한 동작을 확정한다. 코드 레벨 설명은 다루지 않는다.

## 화면 구성 (플랫폼 공통)

앱은 두 개의 화면 키를 가진다.

| 화면 키 | 대응 화면 |
| --- | --- |
| Permission | 권한 요청 화면 ([권한 스펙](permission.md)) |
| Home | 홈 화면 ([홈 스펙](home.md)) |

- 화면 키는 직렬화 가능한 형태로 정의하며, 백스택을 단일 출처로 두고 화면을 전환한다.
- 백스택 복원을 위해 모든 화면 키의 다형성 직렬화를 등록한다. (Android/iOS 공통 동작을 위해 멀티플랫폼 직렬화 방식 사용 — 근거: [컨텍스트](../context/navigation.md))

## 앱 실행 시 시작 화면 (플랫폼 공통)

- 앱이 시작되면 **첫 화면을 그리기 전에** 현재 권한 상태를 읽어 시작 화면을 결정한다.
  - **카메라·마이크·사진 저장·위치 4개 권한이 모두 허용** → 시작 화면은 **Home**.
  - **하나라도 미허용** → 시작 화면은 **Permission**.
- "모두 허용" 판정 기준은 [권한 스펙](permission.md)의 권한 상태 모델을 따른다. (특히 사진 저장 권한의 플랫폼 차이는 권한 스펙의 플랫폼별 분기를 따른다.)

## 권한 화면 → 홈 이동 (플랫폼 공통)

홈 이동은 두 경로로 일어난다.

- **시작 버튼**: 사용자가 시작 버튼을 누르면 이동한다. (버튼의 문구·활성 조건은 [권한 스펙](permission.md))
- **자동 이동**: 권한 화면에 있는 동안 4개 권한이 모두 허용되면 별도 조작 없이 자동으로 이동한다.

어느 경로든 이동 시 **백스택을 Home으로 교체**한다. 즉, 권한 화면을 백스택에 남기지 않는다.

## 뒤로 가기 (플랫폼 공통)

- 홈 화면에서 뒤로 가기를 하면 백스택에 꺼낼 이전 화면이 없으므로 앱을 빠져나간다(권한 화면으로 돌아가지 않는다).
- 이는 시작 화면이 Home인 경우(앱 실행 시 4개 모두 허용)와 권한 화면에서 Home으로 교체 이동한 경우 모두 동일하다.
