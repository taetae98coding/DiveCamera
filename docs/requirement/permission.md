# 권한 요청 (Permission) — 요구사항

> 기획자 관점에서 원하는 동작을 기술한다. 코드/플랫폼 구분은 다루지 않는다.

## 개요

앱이 정상 동작하기 위해 필요한 권한들을 사용자에게 요청하는 화면을 제공한다. 사용자가 각 권한이 왜 필요한지 이해한 상태에서 권한을 허용할 수 있도록 돕고, 권한이 준비되면 매끄럽게 홈 화면으로 이어지게 한다.

## 필요한 권한

다음 4개의 권한을 요청한다.

| 권한 | 용도 (사용자에게 보여줄 설명) |
| --- | --- |
| 카메라 | 다이빙 영상과 사진을 촬영하기 위해 필요하다. |
| 마이크 | 영상에 소리를 함께 녹음하기 위해 필요하다. |
| 사진 저장 | 촬영한 사진과 영상을 갤러리(사진 보관함)에 저장하기 위해 필요하다. |
| 위치 | 촬영 위치(다이빙 포인트)를 기록하기 위해 필요하다. |

- 각 권한 항목에는 **무엇을 위해 필요한지 설명**이 반드시 함께 표시되어야 한다.
- 아직 허용되지 않은 권한만 목록에 노출하며, **허용이 완료된 권한 카드는 목록에서 제거**된다.
- **시작(Start) 버튼**과 **앱 설정 이동 버튼**은 권한 목록과 무관하게 **항상 화면 하단에 노출**된다.

## 동작

### 권한 요청

- 사용자는 권한 요청 화면에서 각 권한을 허용할 수 있다.
- 아직 결정하지 않은 권한은 요청(허용을 묻는 과정)을 진행할 수 있다.

### 홈으로 이동 (시작 버튼)

- 화면 하단의 **시작(Start) 버튼**으로 사용자는 홈 화면으로 이동한다.
- **카메라 권한이 허용되어 있으면** 시작 버튼이 활성화되어 홈으로 이동할 수 있다. (나머지 권한이 없어도 홈으로 이동할 수 있어야 한다.)
- 카메라 권한이 허용되지 않았으면 시작 버튼은 비활성화된다.
- 즉, 홈으로 이동할 수 있는 최소 조건은 "카메라 권한 허용"이다.
- **4개 권한이 모두 허용되면 시작 버튼을 누르지 않아도 자동으로 홈으로 이동**한다.
- 한편 **앱 실행 시점**에 4개 권한이 모두 허용되어 있으면 이 화면을 거치지 않고 곧바로 홈으로 진입한다. (앱 실행 시 라우팅은 [화면 이동 요구사항](../requirement/navigation.md) 참조)

### 거절된 권한 다시 허용하기

- 사용자가 한 번 권한을 거절하면, 이후 다시 요청해도 **권한을 묻는 시스템 창이 더 이상 나타나지 않을 수 있다.**
- 이 경우 사용자가 권한을 되돌릴 방법이 없으면 안 되므로, 화면에서 **앱 설정(권한 설정) 화면으로 이동**할 수 있는 수단을 제공한다.
- 사용자는 앱 설정으로 이동해 직접 권한을 켠 뒤 앱으로 돌아올 수 있다.
